## Dev Notes

### Architecture Constraints

- **Runtime:** Node.js 20+ is required. Verify with `node -v` before starting.
- **Framework:** NestJS 11 (latest). The `--strict` flag on `nest new` enables TypeScript strict mode automatically.
- **Package manager:** npm only (not yarn, not pnpm). Enforced by `--package-manager=npm` flag.
- **SWC compiler:** NestJS 11 defaults to SWC for compilation and Jest transforms. Verify `@swc/core` and `@swc/jest` are in devDependencies after scaffolding.
- **Skip git init:** The `--skip-git` flag is used because the project already has a git repository initialized at the parent level.

### TypeScript Strict Mode Details

The `--strict` flag enables the following in `tsconfig.json`:
- `strictNullChecks` -- prevents `null`/`undefined` from being assigned to non-nullable types
- `noImplicitAny` -- requires explicit types where inference is not possible
- `strictFunctionTypes` -- stricter checking of function parameter types
- `strictBindCallApply` -- strict checking of `bind`, `call`, and `apply`
- `strictPropertyInitialization` -- class properties must be initialized or marked optional
- `noImplicitThis` -- raises error on `this` with an implied `any` type
- `alwaysStrict` -- emits `"use strict"` in every file

Additionally, per project rules, we manually add:
- `noUnusedLocals: true`
- `noUnusedParameters: true`

```json
  "format": "prettier --write \"src/**/*.ts\" \"test/**/*.ts\"",
  "test": "jest",
  "test:watch": "jest --watch",

  "test:debug": "node --inspect-brk -r tsconfig-paths/register -r ts-node/register node_modules/.bin/jest --runInBand",

```

These are CI-ready: `npm run lint` and `npm run test` can be called directly in CI pipelines.

- For this story, only the default scaffold test needs to pass
