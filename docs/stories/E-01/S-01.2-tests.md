## 3. Module Stub Content Validation

Each stub module file must contain valid NestJS module boilerplate and correct class naming.

| ID | File | Check | Expected |
|----|------|-------|----------|
| MC-01 | `users.module.ts` | Imports `Module` from `@nestjs/common` | `import { Module } from '@nestjs/common';` |
| MC-02 | `users.module.ts` | Has `@Module({})` decorator | Present |
| MC-03 | `users.module.ts` | Exports class `UsersModule` | `export class UsersModule {}` |
| MC-04 | `stations.module.ts` | Imports `Module` from `@nestjs/common` | `import { Module } from '@nestjs/common';` |
| MC-05 | `stations.module.ts` | Has `@Module({})` decorator | Present |
| MC-06 | `stations.module.ts` | Exports class `StationsModule` | `export class StationsModule {}` |
| MC-07 | `measurements.module.ts` | Imports `Module` from `@nestjs/common` | `import { Module } from '@nestjs/common';` |
| MC-08 | `measurements.module.ts` | Has `@Module({})` decorator | Present |
| MC-09 | `measurements.module.ts` | Exports class `MeasurementsModule` | `export class MeasurementsModule {}` |
| MC-10 | `notifications.module.ts` | Imports `Module` from `@nestjs/common` | `import { Module } from '@nestjs/common';` |
| MC-11 | `notifications.module.ts` | Has `@Module({})` decorator | Present |
| MC-12 | `notifications.module.ts` | Exports class `NotificationsModule` | `export class NotificationsModule {}` |
| MC-13 | All stubs | No providers, controllers, imports, or exports arrays | `@Module({})` only -- empty decorator |

**Verification script (MC-01 through MC-13):**

```bash
#!/bin/bash
# Run from project root
PASS=0
FAIL=0

check_module_stub() {
  local id_base="$1" file="$2" class_name="$3"

  # Check import
  if grep -q "import { Module } from '@nestjs/common';" "$file" 2>/dev/null; then
    echo "  PASS [${id_base}a]: $file has correct import"
    ((PASS++))
  else
    echo "  FAIL [${id_base}a]: $file missing Module import"
    ((FAIL++))
  fi

  # Check @Module({}) decorator
  if grep -q "@Module({})" "$file" 2>/dev/null; then
    echo "  PASS [${id_base}b]: $file has @Module({}) decorator"
    ((PASS++))
  else
    echo "  FAIL [${id_base}b]: $file missing @Module({}) decorator"
    ((FAIL++))
  fi

  # Check class export
  if grep -q "export class ${class_name} {}" "$file" 2>/dev/null; then
    echo "  PASS [${id_base}c]: $file exports ${class_name}"
    ((PASS++))
  else
    echo "  FAIL [${id_base}c]: $file missing 'export class ${class_name} {}'"
    ((FAIL++))
  fi

  # Check no providers/controllers/imports/exports arrays in decorator
  if grep -qE "(providers|controllers|imports|exports)\s*:" "$file" 2>/dev/null; then
    echo "  FAIL [${id_base}d]: $file has non-empty @Module() -- should be @Module({})"
    ((FAIL++))
  else
    echo "  PASS [${id_base}d]: $file @Module({}) is empty (no arrays)"
    ((PASS++))
  fi
}

echo "=== 3. Module Stub Content Validation ==="
check_module_stub MC-U src/modules/users/users.module.ts UsersModule
check_module_stub MC-S src/modules/stations/stations.module.ts StationsModule
check_module_stub MC-M src/modules/measurements/measurements.module.ts MeasurementsModule
check_module_stub MC-N src/modules/notifications/notifications.module.ts NotificationsModule

echo ""
echo "=============================="
echo "Module content checks -- PASSED: $PASS  FAILED: $FAIL"
echo "=============================="
[ "$FAIL" -eq 0 ] || exit 1
```

## 5. Boundary Rule Validation (Static Analysis)

These checks enforce hexagonal architecture boundary rules at the file level.

### 5.1 Domain Layer Purity

No NestJS or Mongoose framework imports may appear in any `domain/` directory. The domain layer must contain only pure TypeScript.

| ID | Check | Scope | Expected |
|----|-------|-------|----------|
| BR-01 | No `@nestjs/` imports in domain | All `src/modules/*/domain/**/*.ts` files | Zero matches |
| BR-02 | No `mongoose` imports in domain | All `src/modules/*/domain/**/*.ts` files | Zero matches |
| BR-03 | No `@Injectable` decorator in domain | All `src/modules/*/domain/**/*.ts` files | Zero matches |
| BR-04 | No `@Controller` decorator in domain | All `src/modules/*/domain/**/*.ts` files | Zero matches |

### 5.2 Interface Layer Isolation

The interface layer must not directly import from infrastructure repositories.

| ID | Check | Scope | Expected |
|----|-------|-------|----------|
| BR-05 | No `repository` imports in interface | All `src/modules/*/interface/**/*.ts` files | Zero matches for `from.*infrastructure` or `from.*repositories` |
| BR-06 | No Mongoose schema imports in interface | All `src/modules/*/interface/**/*.ts` files | Zero matches for `from.*mongoose` |

### 5.3 App Module Untouched

| ID | Check | Expected |
|----|-------|----------|
| BR-07 | `src/app.module.ts` not modified | File content matches S-01.1 baseline (no new imports for users/stations/measurements/notifications modules) |

**Verification script (BR-01 through BR-07):**

```bash
#!/bin/bash
# Run from project root
PASS=0
FAIL=0

check_no_pattern() {
  local id="$1" pattern="$2" scope="$3" desc="$4"
  local matches
  matches=$(find $scope -name "*.ts" -exec grep -l "$pattern" {} \; 2>/dev/null | head -5)
  if [ -z "$matches" ]; then
    echo "  PASS [$id]: $desc"
    ((PASS++))
  else
    echo "  FAIL [$id]: $desc -- found in: $matches"
    ((FAIL++))
  fi
}

echo "=== 5.1 Domain Layer Purity ==="

check_no_pattern BR-02 "mongoose" "src/modules/*/domain/" "No mongoose imports in domain"
```
