# Story 1.3: Docker Compose for MongoDB

Status: done

## Story

As a developer, I want a Docker Compose configuration with MongoDB 7, so that the team can run the database locally without external dependencies.

## Acceptance Criteria

1. A `docker-compose.yml` file exists at the project root with a MongoDB 7 service definition.
2. The MongoDB service uses the official `mongo:7` Docker image (Atlas-compatible).
3. A Docker health check is configured that verifies MongoDB is accepting connections (using `mongosh --eval "db.adminCommand('ping')"` or equivalent).
4. A named persistent volume (`mongodb_data`) is defined and mounted to `/data/db` so data survives container restarts.
5. The MongoDB container exposes port `27017` on `localhost:27017`.
6. An initial database named `weatherflow` is created via the `MONGO_INITDB_DATABASE` environment variable.
7. The connection string `mongodb://localhost:27017/weatherflow` is documented and matches the `MONGODB_URI` environment variable expected by the application.
8. Running `docker compose up -d` starts MongoDB and the health check reports healthy within 30 seconds.
9. Running `docker compose down` stops the service; running `docker compose down -v` also removes the persistent volume.
10. A `.env.example` file (or update to existing one) documents `MONGODB_URI=mongodb://localhost:27017/weatherflow`.

## Dev Notes

### Project Structure Notes

The `docker-compose.yml` must be placed at the **project root** so that `docker compose up` works without extra flags. The file should be minimal and focused on the MongoDB service only; additional services (e.g., the NestJS app) will be added in later stories.

**Target `docker-compose.yml` structure:**

```yaml
version: "3.9"

services:
  mongodb:
    image: mongo:7
    container_name: weatherflow-mongodb
    restart: unless-stopped
    ports:
      - "27017:27017"
    environment:
      MONGO_INITDB_DATABASE: weatherflow
    volumes:
      - mongodb_data:/data/db
    healthcheck:
      test: ["CMD", "mongosh", "--eval", "db.adminCommand('ping')"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s

volumes:
  mongodb_data:
    driver: local
```

**Key decisions:**

- **No authentication for local dev:** For simplicity in the local development environment, MongoDB runs without `MONGO_INITDB_ROOT_USERNAME` / `MONGO_INITDB_ROOT_PASSWORD`. The production environment (MongoDB Atlas) handles authentication separately. If authentication is needed later, it can be added without breaking the compose file.
- **mongo:7 image:** Chosen for compatibility with MongoDB Atlas (which runs MongoDB 7.x). This ensures feature parity between local development and production.
- **mongosh for health check:** MongoDB 7 ships with `mongosh` as the default shell (legacy `mongo` shell is removed), so the health check uses `mongosh`.
- **Named volume:** Using a named volume (`mongodb_data`) instead of a bind mount provides better portability across operating systems (Windows, macOS, Linux).

**Connection string format:**

```
mongodb://localhost:27017/weatherflow
```

This should be set as the `MONGODB_URI` environment variable in the application's `.env` file. The NestJS application (configured in a later story) will read this variable to establish the Mongoose connection.
