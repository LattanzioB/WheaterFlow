| DC-16 | Restart policy is `unless-stopped`                                 | Automated | `services.mongodb.restart` equals `unless-stopped`                                                   |

## 3. Runtime Verification (Manual / CI)

> **Prerequisite:** Docker Engine and Docker Compose V2 are installed and the Docker daemon is running.

| ID    | Description                                                            | Type   | Steps                                                                                                              | Expected Result                                                                                  |
|-------|------------------------------------------------------------------------|--------|----------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------|
| DC-17 | `docker compose up -d` starts successfully                             | Manual | Run `docker compose up -d` from project root                                                                        | Command exits with code 0; `docker compose ps` shows `weatherflow-mongodb` with status `running` |
| DC-18 | Health check reports healthy within 30 seconds                         | Manual | After DC-17, run `docker compose ps` repeatedly or use `--wait` flag                                                | Service status shows `healthy` within 30 seconds of startup                                      |
| DC-19 | MongoDB accepts connections on `localhost:27017`                       | Manual | Run `mongosh --host localhost --port 27017 --eval "db.runCommand({ping:1})"` (or use a MongoDB client/driver)       | Command succeeds and returns `{ ok: 1 }`                                                         |
| DC-20 | Database `weatherflow` exists after first startup                      | Manual | Connect to MongoDB and run `show dbs`                                                                               | `weatherflow` database appears in the list (may be empty until data is inserted)                 |
| DC-21 | `docker compose down` stops the service cleanly                        | Manual | Run `docker compose down` from project root                                                                          | Command exits with code 0; `docker compose ps` returns empty; volume `mongodb_data` still exists |
| DC-22 | Data persists across restarts                                          | Manual | 1. `docker compose up -d` 2. Insert a document 3. `docker compose down` 4. `docker compose up -d` 5. Query document | Inserted document is retrievable after restart                                                   |
| DC-23 | `docker compose down -v` removes the persistent volume                 | Manual | Run `docker compose down -v` from project root                                                                       | Command exits with code 0; `docker volume ls` no longer lists `mongodb_data`                     |

## Automation Script Reference

The following static checks (DC-01 through DC-16, DC-25, DC-26) can be automated in CI with a script similar to:

```bash
#!/usr/bin/env bash
set -euo pipefail

# DC-01: docker-compose.yml exists
test -f docker-compose.yml && echo "DC-01 PASS" || echo "DC-01 FAIL"

# DC-02: .env.example exists
test -f .env.example && echo "DC-02 PASS" || echo "DC-02 FAIL"

# DC-03: docker compose config parses
docker compose config > /dev/null 2>&1 && echo "DC-03 PASS" || echo "DC-03 FAIL"

# DC-04: mongodb service exists
docker compose config --services | grep -q '^mongodb$' && echo "DC-04 PASS" || echo "DC-04 FAIL"

# DC-05: image is mongo:7 or mongo:7.x
docker compose config | grep -qE 'image:\s*mongo:7(\.\d+)?' && echo "DC-05 PASS" || echo "DC-05 FAIL"

# DC-06: port 27017 mapped
docker compose config | grep -q '27017:27017' && echo "DC-06 PASS" || echo "DC-06 FAIL"

# DC-07: named volume mongodb_data at top level
docker compose config | grep -qE '^volumes:' && docker compose config | grep -q 'mongodb_data' && echo "DC-07 PASS" || echo "DC-07 FAIL"

# DC-09: healthcheck uses mongosh
docker compose config | grep -q 'mongosh' && echo "DC-09 PASS" || echo "DC-09 FAIL"

# DC-14: MONGO_INITDB_DATABASE is weatherflow
docker compose config | grep -q 'MONGO_INITDB_DATABASE.*weatherflow' && echo "DC-14 PASS" || echo "DC-14 FAIL"

# DC-25: .env.example contains MONGODB_URI
grep -q 'MONGODB_URI=mongodb://localhost:27017/weatherflow' .env.example && echo "DC-25 PASS" || echo "DC-25 FAIL"
```
