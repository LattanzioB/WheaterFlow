# Story 1.4: Environment Configuration

Status: ready-for-dev

## Story

As a **developer**, I want environment configuration managed via `@nestjs/config`, so that sensitive values are externalized and the app is configurable across environments (development, staging, production) without code changes.

## Acceptance Criteria

1. **AC-1:** A `.env.example` file exists at the project root containing all required environment variables with placeholder values and inline comments.
2. **AC-2:** A configuration factory function at `src/shared/config/configuration.ts` reads environment variables and exports a typed configuration object.
3. **AC-3:** `ConfigModule.forRoot()` is imported globally in `app.module.ts` with the configuration factory and validation enabled.
4. **AC-4:** The application fails fast on startup if any required environment variable is missing or invalid (Joi schema validation).
5. **AC-5:** `.env` is listed in `.gitignore`; `.env.example` is committed to the repository.
6. **AC-6:** `ConfigService` can be injected into any module/service without re-importing `ConfigModule`.
7. **AC-7:** All environment variables follow `SCREAMING_SNAKE_CASE` naming convention; their mapped TypeScript properties follow `camelCase`.

```dotenv
# --- Authentication ---
JWT_SECRET=your-secret-key
JWT_EXPIRES_IN=7d

# --- Telegram Notifications ---
TELEGRAM_BOT_TOKEN=your-bot-token
```

### Configuration Factory (`src/shared/config/configuration.ts`)

```typescript
export default () => ({
  port: parseInt(process.env.PORT, 10) || 3000,
  database: {
    uri: process.env.MONGODB_URI,
  },
  jwt: {
    secret: process.env.JWT_SECRET,
    expiresIn: process.env.JWT_EXPIRES_IN || '7d',
  },
  telegram: {
    botToken: process.env.TELEGRAM_BOT_TOKEN,
  },
});
```

### Joi Validation Schema (`src/shared/config/env-validation.ts`)

```typescript
import * as Joi from 'joi';

export const envValidationSchema = Joi.object({
  PORT: Joi.number().default(3000),
  MONGODB_URI: Joi.string().required().messages({
    'any.required': 'MONGODB_URI is required. Set it in your .env file.',
  }),
  JWT_SECRET: Joi.string().required().min(8).messages({
    'any.required': 'JWT_SECRET is required. Set it in your .env file.',
    'string.min': 'JWT_SECRET must be at least 8 characters long.',
  }),
  JWT_EXPIRES_IN: Joi.string().default('7d'),
  TELEGRAM_BOT_TOKEN: Joi.string().optional().allow(''),
});
```

### ConfigModule Registration (`app.module.ts`)

```typescript
import { ConfigModule } from '@nestjs/config';
import configuration from './shared/config/configuration';
import { envValidationSchema } from './shared/config/env-validation';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      load: [configuration],
      validationSchema: envValidationSchema,
      validationOptions: {
        abortEarly: false, // report all errors, not just the first
      },
    }),
    // ... other modules
  ],
})
export class AppModule {}
```

### Usage Example (Injecting ConfigService)

```typescript
import { ConfigService } from '@nestjs/config';

@Injectable()
export class SomeService {
  constructor(private readonly configService: ConfigService) {}

  getDatabaseUri(): string {
    return this.configService.get<string>('database.uri');
  }

  getJwtSecret(): string {
    return this.configService.get<string>('jwt.secret');
  }
}
```

### Key Decisions

- **Joi over class-validator for env validation:** Joi integrates natively with `ConfigModule.forRoot({ validationSchema })` and provides richer schema validation for environment variables. `class-validator` is better suited for DTO validation at the controller layer.
- **`isGlobal: true`:** Avoids importing `ConfigModule` in every feature module. `ConfigService` is available for injection everywhere.
- **`TELEGRAM_BOT_TOKEN` is optional:** Notifications module may not be configured in all environments (e.g., test). The app should start without it and log a warning.
- **`abortEarly: false`:** Reports all validation errors at once so developers can fix everything in a single pass.
