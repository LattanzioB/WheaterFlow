## 1. File Existence Checks

These checks verify that all configuration files exist and contain the expected content.

### 1.1 Configuration Files

| ID | Check | Expected |
|----|-------|----------|
| EC-01 | `src/shared/config/configuration.ts` exists | yes |
| EC-02 | `src/shared/config/env-validation.ts` exists | yes |
| EC-03 | `.env.example` exists at project root | yes |

### 1.2 `.env.example` Variable Presence

| ID | Variable | Must be present in `.env.example` |
|----|----------|-----------------------------------|
| EC-04 | `PORT` | yes |
| EC-05 | `MONGODB_URI` | yes |
| EC-06 | `JWT_SECRET` | yes |
| EC-07 | `JWT_EXPIRES_IN` | yes |
| EC-08 | `TELEGRAM_BOT_TOKEN` | yes |

**Verification script:**

```bash
#!/bin/bash
# Run from weatherflow/ root
if [ ! -f .env.example ]; then
  echo "FAIL: .env.example does not exist"
  exit 1
fi
ENV_VARS=("PORT" "MONGODB_URI" "JWT_SECRET" "JWT_EXPIRES_IN" "TELEGRAM_BOT_TOKEN")
for var in "${ENV_VARS[@]}"; do
  if ! grep -q "^${var}=" .env.example; then
    echo "FAIL: .env.example missing variable '$var'"
    exit 1
  fi
done
echo "PASS: .env.example contains all 5 required variables"
```

### 1.3 `.env` Gitignore Verification

| ID | Check | Expected |
|----|-------|----------|
| EC-09 | `.gitignore` contains `.env` entry | `.env` line present (must not match `.env.example`) |
| EC-10 | `.env.example` is NOT in `.gitignore` | `.env.example` must be committable |

**Verification script:**

```bash
#!/bin/bash
# Run from weatherflow/ root
if grep -qE '^\\.env$' .gitignore; then
  echo "PASS: .env is in .gitignore"
else
  echo "FAIL: .env is NOT in .gitignore"
  exit 1
fi
if grep -q '\.env\.example' .gitignore; then
  echo "FAIL: .env.example should NOT be in .gitignore"
  exit 1
else
  echo "PASS: .env.example is not gitignored"
fi
```

## 2. Configuration Unit Tests (Jest)

These tests must be implemented in `src/shared/config/configuration.spec.ts` and pass via `npm run test`.

### 2.1 Configuration Factory Shape (`configuration.spec.ts`)

| ID | Test Description | Expected |
|----|-----------------|----------|
| EC-11 | Configuration factory returns an object | `typeof configuration() === 'object'` |
| EC-12 | Returned object has `port` key (number) | `config.port` is a number |
| EC-13 | Returned object has `database.uri` key | `config.database.uri` is defined |
| EC-14 | Returned object has `jwt.secret` key | `config.jwt.secret` is defined |
| EC-15 | Returned object has `jwt.expiresIn` key | `config.jwt.expiresIn` is defined |
| EC-16 | Returned object has `telegram.botToken` key | `config.telegram` has `botToken` property |

**Expected test file (`src/shared/config/configuration.spec.ts`):**

```typescript
import configuration from './configuration';

describe('configuration factory', () => {
  const ORIGINAL_ENV = process.env;

  beforeEach(() => {
    jest.resetModules();
    process.env = { ...ORIGINAL_ENV };
  });

  afterAll(() => {
    process.env = ORIGINAL_ENV;
  });

  // EC-11
  it('should return an object', () => {
    process.env.PORT = '4000';
    process.env.MONGODB_URI = 'mongodb://localhost:27017/test';
    process.env.JWT_SECRET = 'test-secret-key';
    process.env.JWT_EXPIRES_IN = '1d';
    process.env.TELEGRAM_BOT_TOKEN = 'test-token';

    const config = configuration();
    expect(typeof config).toBe('object');
  });

  // EC-12
  it('should map PORT to port as a number', () => {
    process.env.PORT = '4000';
    const config = configuration();
    expect(config.port).toBe(4000);
    expect(typeof config.port).toBe('number');
  });

  // EC-13
  it('should map MONGODB_URI to database.uri', () => {
    process.env.MONGODB_URI = 'mongodb://localhost:27017/test';
    const config = configuration();
    expect(config.database.uri).toBe('mongodb://localhost:27017/test');
  });

  // EC-14
  it('should map JWT_SECRET to jwt.secret', () => {
    process.env.JWT_SECRET = 'my-super-secret';
    const config = configuration();
    expect(config.jwt.secret).toBe('my-super-secret');
  });

  // EC-15
  it('should map JWT_EXPIRES_IN to jwt.expiresIn', () => {
    process.env.JWT_EXPIRES_IN = '24h';
    const config = configuration();
    expect(config.jwt.expiresIn).toBe('24h');
  });

  // EC-16
  it('should map TELEGRAM_BOT_TOKEN to telegram.botToken', () => {
    process.env.TELEGRAM_BOT_TOKEN = 'bot123:token';
    const config = configuration();
    expect(config.telegram.botToken).toBe('bot123:token');
  });
});
```

## 3. Validation Tests (Jest)

These tests must be implemented in `src/shared/config/env-validation.spec.ts` and verify the Joi schema.

### 3.1 Required Variable Validation

| ID | Test Description | Expected |
|----|-----------------|----------|
| EC-20 | Validation fails when MONGODB_URI is missing | Joi returns error with `MONGODB_URI` message |
| EC-21 | Validation fails when JWT_SECRET is missing | Joi returns error with `JWT_SECRET` message |
| EC-22 | Validation fails when JWT_SECRET is shorter than 8 characters | Joi returns error with `string.min` message |
| EC-23 | Validation fails when both MONGODB_URI and JWT_SECRET are missing | Joi returns errors for both (abortEarly: false) |

### 3.2 Optional Variable Validation

| ID | Test Description | Expected |
|----|-----------------|----------|
| EC-24 | Validation passes when TELEGRAM_BOT_TOKEN is missing | No error for TELEGRAM_BOT_TOKEN |
| EC-25 | Validation passes when TELEGRAM_BOT_TOKEN is empty string | No error |
| EC-26 | PORT defaults to 3000 via Joi when not provided | `value.PORT === 3000` |
| EC-27 | JWT_EXPIRES_IN defaults to `'7d'` via Joi when not provided | `value.JWT_EXPIRES_IN === '7d'` |

### 3.3 Valid Configuration

| ID | Test Description | Expected |
|----|-----------------|----------|
| EC-28 | Validation passes with all required vars present | No errors; value object contains all keys |
| EC-29 | PORT is coerced to number | `typeof value.PORT === 'number'` |

**Expected test file (`src/shared/config/env-validation.spec.ts`):**

```typescript
import { envValidationSchema } from './env-validation';

describe('envValidationSchema', () => {
  const validEnv = {
    PORT: 3000,
    MONGODB_URI: 'mongodb://localhost:27017/weatherflow',
    JWT_SECRET: 'super-secret-key-12345',
    JWT_EXPIRES_IN: '7d',
    TELEGRAM_BOT_TOKEN: 'bot123:ABC-DEF',
  };

  // EC-28
  it('should pass with all required variables present', () => {
    const { error } = envValidationSchema.validate(validEnv);
    expect(error).toBeUndefined();
  });

  // EC-20
  it('should fail when MONGODB_URI is missing', () => {
    const { MONGODB_URI, ...env } = validEnv;
    const { error } = envValidationSchema.validate(env, { abortEarly: false });
    expect(error).toBeDefined();
    expect(error.message).toContain('MONGODB_URI');
  });

  // EC-21
  it('should fail when JWT_SECRET is missing', () => {
    const { JWT_SECRET, ...env } = validEnv;
    const { error } = envValidationSchema.validate(env, { abortEarly: false });
    expect(error).toBeDefined();
    expect(error.message).toContain('JWT_SECRET');
  });

  // EC-22
  it('should fail when JWT_SECRET is shorter than 8 characters', () => {
    const env = { ...validEnv, JWT_SECRET: 'short' };
    const { error } = envValidationSchema.validate(env);
    expect(error).toBeDefined();
    expect(error.message).toContain('JWT_SECRET');
  });

  // EC-23
  it('should report multiple errors when both MONGODB_URI and JWT_SECRET are missing', () => {
    const { MONGODB_URI, JWT_SECRET, ...env } = validEnv;
    const { error } = envValidationSchema.validate(env, { abortEarly: false });
    expect(error).toBeDefined();
    expect(error.details.length).toBeGreaterThanOrEqual(2);
    const fields = error.details.map((d: any) => d.context?.key);
    expect(fields).toContain('MONGODB_URI');
    expect(fields).toContain('JWT_SECRET');
  });

  // EC-24
  it('should pass when TELEGRAM_BOT_TOKEN is missing', () => {
    const { TELEGRAM_BOT_TOKEN, ...env } = validEnv;
    const { error } = envValidationSchema.validate(env);
    expect(error).toBeUndefined();
  });

  // EC-25
  it('should pass when TELEGRAM_BOT_TOKEN is empty string', () => {
    const env = { ...validEnv, TELEGRAM_BOT_TOKEN: '' };
    const { error } = envValidationSchema.validate(env);
    expect(error).toBeUndefined();
  });

  // EC-26
  it('should default PORT to 3000 when not provided', () => {
    const { PORT, ...env } = validEnv;
    const { error, value } = envValidationSchema.validate(env);
    expect(error).toBeUndefined();
    expect(value.PORT).toBe(3000);
  });

  // EC-27
  it('should default JWT_EXPIRES_IN to "7d" when not provided', () => {
    const { JWT_EXPIRES_IN, ...env } = validEnv;
    const { error, value } = envValidationSchema.validate(env);
    expect(error).toBeUndefined();
    expect(value.JWT_EXPIRES_IN).toBe('7d');
  });

  // EC-29
  it('should coerce PORT to a number', () => {
    const env = { ...validEnv, PORT: '8080' };
    const { error, value } = envValidationSchema.validate(env);
    expect(error).toBeUndefined();
    expect(value.PORT).toBe(8080);
    expect(typeof value.PORT).toBe('number');
  });
});
```

## 4. Integration Checks

These checks verify that the configuration module is properly wired into the NestJS application.

### 4.1 Module Registration

| ID | Check | How to Verify | Expected |
|----|-------|---------------|----------|
| EC-30 | `ConfigModule.forRoot()` is in `app.module.ts` imports | `grep -q 'ConfigModule.forRoot' src/app.module.ts` | Match found |
| EC-31 | `isGlobal: true` is set in ConfigModule options | `grep -q 'isGlobal.*true' src/app.module.ts` | Match found |
| EC-32 | Configuration factory is wired via `load` option | `grep -q 'load.*configuration' src/app.module.ts` | Match found |
| EC-33 | Joi validation schema is wired via `validationSchema` | `grep -q 'validationSchema.*envValidationSchema' src/app.module.ts` | Match found |

**Verification script:**

```bash
#!/bin/bash
# Run from weatherflow/ root
CHECKS=(
  "ConfigModule.forRoot:ConfigModule.forRoot"
  "isGlobal: true:isGlobal.*true"
  "load option:load.*configuration"
  "validationSchema:validationSchema.*envValidationSchema"
)
for check in "${CHECKS[@]}"; do
  IFS=':' read -r label pattern <<< "$check"
  if grep -qE "$pattern" src/app.module.ts; then
    echo "PASS: $label found in app.module.ts"
  else
    echo "FAIL: $label NOT found in app.module.ts"
    exit 1
  fi
done
echo "All module registration checks passed"
```

### 4.2 ConfigService Injectable

| ID | Check | Expected |
|----|-------|----------|
| EC-34 | ConfigService is injectable without importing ConfigModule in a child module | A test module can resolve `ConfigService` when only `AppModule` imports `ConfigModule` globally |

**Expected integration test (can be placed in `src/shared/config/config-integration.spec.ts` or inline in an existing spec):**

```typescript
import { Test, TestingModule } from '@nestjs/testing';
import { ConfigModule, ConfigService } from '@nestjs/config';
import configuration from './configuration';
import { envValidationSchema } from './env-validation';

describe('ConfigService integration', () => {
  let configService: ConfigService;

  beforeEach(async () => {
    const module: TestingModule = await Test.createTestingModule({
      imports: [
        ConfigModule.forRoot({
          isGlobal: true,
          load: [configuration],
          validationSchema: envValidationSchema,
          // Provide env vars for test
          envFilePath: '.env.example',
        }),
      ],
    }).compile();

    configService = module.get<ConfigService>(ConfigService);
  });

  // EC-34
  it('should resolve ConfigService', () => {
    expect(configService).toBeDefined();
  });

  it('should access nested config keys', () => {
    const port = configService.get<number>('port');
    expect(port).toBeDefined();
    expect(typeof port).toBe('number');
  });
});
```

## 5. App Startup Behavior Tests

These are manual or scripted checks that validate the app's fail-fast behavior.

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-37 | Start app with no `.env` and no env vars set | App fails to start; error message mentions missing MONGODB_URI and JWT_SECRET |
| EC-38 | Start app with only PORT set | App fails to start; error message mentions MONGODB_URI and JWT_SECRET |
| EC-39 | Start app with PORT, MONGODB_URI, JWT_SECRET set | App starts successfully (TELEGRAM_BOT_TOKEN and JWT_EXPIRES_IN use defaults or are optional) |
| EC-40 | Start app with all 5 vars set | App starts successfully |
| EC-41 | Start app without TELEGRAM_BOT_TOKEN | App starts successfully (TELEGRAM_BOT_TOKEN is optional) |

**Verification script:**

```bash
#!/bin/bash

# EC-37: Should fail with no env vars
echo "=== EC-37: No env vars ==="

if timeout 10 node dist/main.js 2>&1 | grep -qi "error\|validation"; then
  echo "PASS: App fails with validation error when no env vars set"
else
  echo "FAIL: App should fail with validation error"
fi

# EC-39: Should succeed with required vars
echo ""
echo "=== EC-39: Required vars only ==="
export PORT=3001
export MONGODB_URI="mongodb://localhost:27017/weatherflow-test"
export JWT_SECRET="test-secret-key-long-enough"
unset TELEGRAM_BOT_TOKEN
timeout 5 node dist/main.js &
APP_PID=$!

if kill -0 $APP_PID 2>/dev/null; then
  echo "PASS: App starts with required vars only"
  kill $APP_PID 2>/dev/null
else
  echo "FAIL: App should start with required vars"
fi

# EC-41: Should succeed without TELEGRAM_BOT_TOKEN
echo ""
echo "=== EC-41: Without TELEGRAM_BOT_TOKEN ==="
export PORT=3002
unset TELEGRAM_BOT_TOKEN
timeout 5 node dist/main.js &
APP_PID=$!
sleep 3
if kill -0 $APP_PID 2>/dev/null; then
  echo "PASS: App starts without TELEGRAM_BOT_TOKEN"
  kill $APP_PID 2>/dev/null
else
  echo "FAIL: App should start without TELEGRAM_BOT_TOKEN"
fi
```

## 6. Combined Validation Script

A single script the Dev agent can run to validate all file-level and integration checks.

```bash
#!/bin/bash
# S-01.4 Full Validation Script
# Run from weatherflow/ root
set -e
PASS=0
FAIL=0

check() {
  local desc="$1"
  shift
  if eval "$@" > /dev/null 2>&1; then
    echo "  PASS: $desc"
    ((PASS++))
  else
    echo "  FAIL: $desc"
    ((FAIL++))
  fi
}

echo "=== Section 1: File Existence (EC-01 to EC-03) ==="
check "EC-01: configuration.ts exists" "test -f src/shared/config/configuration.ts"
check "EC-02: env-validation.ts exists" "test -f src/shared/config/env-validation.ts"
check "EC-03: .env.example exists" "test -f .env.example"

echo ""
echo "=== Section 2: .env.example Variables (EC-04 to EC-08) ==="
for var in PORT MONGODB_URI JWT_SECRET JWT_EXPIRES_IN TELEGRAM_BOT_TOKEN; do
  check "EC-0$((${#var})): .env.example has $var" "grep -q '^${var}=' .env.example"
done

echo ""
echo "=== Section 3: .gitignore (EC-09 to EC-10) ==="
check "EC-09: .env in .gitignore" "grep -qE '^\\.env$' .gitignore"
check "EC-10: .env.example NOT in .gitignore" "! grep -q '\\.env\\.example' .gitignore"

echo ""
echo "=== Section 4: Module Registration (EC-30 to EC-33) ==="
check "EC-30: ConfigModule.forRoot in app.module.ts" "grep -q 'ConfigModule.forRoot' src/app.module.ts"
check "EC-31: isGlobal: true" "grep -qE 'isGlobal.*true' src/app.module.ts"
check "EC-32: load option with configuration" "grep -qE 'load.*configuration' src/app.module.ts"
check "EC-33: validationSchema wired" "grep -qE 'validationSchema.*envValidationSchema' src/app.module.ts"

echo ""
echo "=== Section 5: Build & Test (EC-35 to EC-36) ==="
check "EC-35: npm run build" "npm run build"
check "EC-36: npm run test" "npm run test"

echo ""
echo "=============================="
echo "PASSED: $PASS"
echo "FAILED: $FAIL"
echo "=============================="
[ "$FAIL" -eq 0 ] && echo "ALL CHECKS PASSED" || echo "SOME CHECKS FAILED"
exit $FAIL
```
