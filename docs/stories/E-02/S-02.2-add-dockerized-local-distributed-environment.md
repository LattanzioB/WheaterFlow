# Story 2.2: Add Dockerized Local Distributed Environment

Status: draft

## Story

As a developer,
I want the API service, Notification service, MongoDB, and RabbitMQ to run locally through Docker Compose,
so that Delivery II can demonstrate a real distributed system with separate service containers.

## Acceptance Criteria

1. `docker-compose.yml` defines separate services for API, Notification service, MongoDB, and RabbitMQ.
2. API and Notification service are built from separate Dockerfiles or separate Docker build targets.
3. API and Notification service expose different HTTP ports.
4. RabbitMQ management UI is available locally for inspection.
5. Environment variables are documented for both services.
6. Health checks or startup dependencies make local startup reliable.
7. `docker compose up --build` starts all services successfully.
8. README/setup docs explain how to run and verify the distributed environment.

## Tasks / Subtasks

- [ ] Task 1: Add Docker images for both applications (AC: #2)
  - [ ] 1.1 Create an API Dockerfile or Docker target.
  - [ ] 1.2 Create a Notification service Dockerfile or Docker target.
  - [ ] 1.3 Ensure each image starts the correct Nest app.

- [ ] Task 2: Extend Docker Compose (AC: #1, #3, #4)
  - [ ] 2.1 Keep the existing MongoDB service.
  - [ ] 2.2 Add RabbitMQ using the management image.
  - [ ] 2.3 Add API service on port `3000`.
  - [ ] 2.4 Add Notification service on port `3001`.
  - [ ] 2.5 Configure internal service names for container-to-container communication.

- [ ] Task 3: Add service configuration (AC: #5)
  - [ ] 3.1 Add API env vars for MongoDB, JWT, Notification service URL, and RabbitMQ.
  - [ ] 3.2 Add Notification service env vars for MongoDB, RabbitMQ, and notification runtime options.
  - [ ] 3.3 Update `.env.example` with all required variables.
  - [ ] 3.4 Add Joi validation for new env vars.

- [ ] Task 4: Improve startup reliability (AC: #6, #7)
  - [ ] 4.1 Add health checks for MongoDB and RabbitMQ.
  - [ ] 4.2 Configure service dependencies using Compose health conditions where supported.
  - [ ] 4.3 Verify `docker compose up --build` starts all services.

- [ ] Task 5: Update run documentation (AC: #8)
  - [ ] 5.1 Document local URLs for API, Notification service, Swagger, and RabbitMQ management.
  - [ ] 5.2 Document smoke-test commands for both services.

## Dev Notes

- RabbitMQ is the selected message queue for Delivery II.
- Telegram is optional for this delivery. A log/fake notifier is acceptable as long as queue publication and consumption are real.
- Keep MongoDB local unless a separate Atlas requirement is reintroduced.
