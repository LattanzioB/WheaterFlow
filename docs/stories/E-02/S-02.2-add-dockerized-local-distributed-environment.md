# Story 2.2: Add Dockerized Local Distributed Environment

Status: complete

## Story

As a developer,
I want the API service, Notification service, and RabbitMQ to run locally through Docker Compose while MongoDB runs on Atlas,
so that Delivery II can demonstrate a real distributed system with separate service containers and a managed database dependency.

## Acceptance Criteria

1. `docker-compose.yml` defines separate services for API, Notification service, and RabbitMQ; it does not define or build a MongoDB container.
2. API and Notification service are built from separate Dockerfiles or separate Docker build targets.
3. API and Notification service expose different HTTP ports.
4. RabbitMQ management UI is available locally for inspection.
5. Environment variables are documented for both services.
6. Health checks or startup dependencies make local startup reliable.
7. `docker compose up --build` starts the local services successfully while both applications connect to MongoDB Atlas through `MONGODB_URI`.
8. README/setup docs explain how to run and verify the distributed environment, including the Atlas connection requirement.

## Dev Notes

- RabbitMQ is the selected message queue for Delivery II.
- Telegram is optional for this delivery. A log/fake notifier is acceptable as long as queue publication and consumption are real.
- MongoDB is hosted on MongoDB Atlas. Do not build or run a MongoDB image in Docker Compose; configure both services with the Atlas `MONGODB_URI`.
