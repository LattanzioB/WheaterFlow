# Story 2.6: Complete Station And Measurement Search Filters

Status: draft

## Story

As an API client,
I want to search stations and measurements by the required criteria,
so that Delivery II exposes station/measurement search, date range filtering, and climate-parameter filtering through the API.

## Acceptance Criteria

1. Stations can be searched by station name through the API.
2. Measurements can be searched by station name.
3. Measurements can be filtered by date range.
4. Measurements can be filtered by temperature range, greater-than, and less-than semantics.
5. Measurements can be filtered by humidity range, greater-than, and less-than semantics.
6. Measurements can be filtered by pressure range, greater-than, and less-than semantics.
7. Invalid ranges return a clear `400` response.
8. Repository queries are covered by unit tests or integration-style repository tests with mocked models.
9. API docs and DTOs document all query parameters.

## Dev Notes

- Current implementation only supports station name, temperature min/max, and alert-only filters.
- The requirement says ranges, greater than, and less than. Min-only and max-only parameters satisfy greater-than/less-than semantics if documented clearly.
- Date range should use ISO-8601 query values and map to `Date` only after DTO validation.
