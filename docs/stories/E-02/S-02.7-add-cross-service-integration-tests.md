# Story 2.7: Add Cross-Service Integration Tests

Status: draft

## Story

As a developer,
I want automated integration tests that exercise communication between the API and Notification service,
so that Delivery II proves the services interact through real remote boundaries rather than manual Postman calls.

## Acceptance Criteria

1. Integration tests start or connect to test instances of API, Notification service, RabbitMQ, and a MongoDB Atlas test database.
2. Tests verify alert publication from the API service to RabbitMQ.
3. Tests verify Notification service consumes a published alert and invokes the configured fake/log notifier.
4. Tests verify API-to-Notification REST communication for notification preference workflows if proxy routes are kept.
5. Tests do not require Telegram or any external network service.
6. Tests are runnable through an npm script.
7. Test setup and teardown clean queues and test collections.
8. Documentation explains why these are integration tests and not Postman/manual simulations.

## Tasks / Subtasks

- [ ] Task 1: Create integration test infrastructure (AC: #1, #6, #7)
  - [ ] 1.1 Add a Jest integration config.
  - [ ] 1.2 Add `test:integration` script.
  - [ ] 1.3 Provide test env vars for API, Notification service, MongoDB Atlas, and RabbitMQ.
  - [ ] 1.4 Clean test collections and queues before/after tests.

- [ ] Task 2: Test queue-based alert delivery (AC: #2, #3, #5)
  - [ ] 2.1 Start API-side publisher with RabbitMQ test config.
  - [ ] 2.2 Start Notification consumer with fake notifier.
  - [ ] 2.3 Record or publish an alert-producing measurement.
  - [ ] 2.4 Assert fake notifier receives the expected alert payload.

- [ ] Task 3: Test REST service communication (AC: #4)
  - [ ] 3.1 If API proxy routes remain, call the API route.
  - [ ] 3.2 Assert the Notification service stores/updates the preference.
  - [ ] 3.3 Assert the API returns an expected response.

- [ ] Task 4: Document integration test scope (AC: #8)
  - [ ] 4.1 Document what processes/resources are included.
  - [ ] 4.2 Document why Postman/manual calls are not accepted as integration tests.

## Dev Notes

- Prefer real RabbitMQ for at least one integration test because queue behavior is central to the delivery requirement.
- Use a dedicated MongoDB Atlas test database or collection prefix for integration tests; do not add a MongoDB Docker service.
- Fake notifier should be injectable and observable from tests.
- Keep tests deterministic by avoiding real timeouts where possible. Use bounded waits around queue consumption.
