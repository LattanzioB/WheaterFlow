# Story 2.8: Update Distributed Architecture Documentation

Status: done

## Story

As a reviewer,
I want updated architecture documentation for the distributed version of WeatherFlow,
so that the component split, responsibilities, communication flows, and testing strategy are explicit and defensible.

## Acceptance Criteria

1. Architecture document describes the new two-component distributed system.
2. New architecture diagram shows API service, Notification service, RabbitMQ, MongoDB Atlas, and clients.
3. Responsibilities of each component are listed clearly.
4. Technical justification explains the split using granularity breakers and transaction/data boundaries.
5. Sequence diagram documents station/measurement searching and filtering.
6. Sequence diagram documents measurement recording, alert detection, queue publication, and notification consumption.
7. Sequence diagram documents notification preference management across services.
8. Integration-test section explains the implemented automated tests and their scope.
9. Existing docs that still describe only a monolith are updated or clearly marked as Delivery I.
