# Historia 3.1: Extender modelo de estación con proveedor climático

Estado: borrador

## Historia

Como operador del sistema,
quiero que cada estación meteorológica declare un proveedor climático externo opcional y coordenadas de ubicación,
para que el servicio ingest pueda identificar qué estaciones consultar en OpenWeatherMap sin modificar el dominio central de mediciones.

## Criterios de aceptación

1. `WeatherStation` (dominio) y el schema de persistencia soportan un campo opcional `weatherProvider` (p. ej., `manual`, `openweather`).
2. La ubicación de la estación almacena latitud y longitud utilizables como coordenadas de consulta OWM.
3. Los DTOs de la API y Swagger documentan el campo proveedor en create/update/read donde corresponda.
4. Las estaciones con reportes manuales existentes siguen funcionando cuando `weatherProvider` está ausente o es `manual`.
5. Tests unitarios cubren validación de dominio y round-trip del mapper para el nuevo campo.
6. Existe endpoint o query param para listar estaciones filtradas por proveedor (consumido por ingest en S-03.5).

## Tareas / subtareas

  - [ ] 1.3 Asegurar que `Location` expone lat/lon requeridos por OWM.

- [ ] Tarea 2: Actualizar persistencia y capa API (CA: #3, #5, #6)

  - [ ] 2.3 Agregar filtro por proveedor en listado de estaciones.

- [ ] Tarea 3: Agregar tests (CA: #5)

## Notas de desarrollo

- Mantener el proveedor como metadata del agregado estación; no embeber campos específicos de OWM (API keys, unidades) en la entidad de dominio.
- El seed de estaciones default queda en S-03.2; esta historia solo habilita el modelo.
- Puede ejecutarse en paralelo con S-03.3 (scaffold ingest).
