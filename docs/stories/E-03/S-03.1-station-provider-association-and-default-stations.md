# Story 3.1: Station↔Provider Association, Measurement Source And Default Stations

Status: draft

## Story

As a station administrator,
I want stations to declare a climate provider and measurements to record their source,
so that the system knows which stations OpenWeatherMap should feed and can distinguish externally ingested data from manual reports.

## Acceptance Criteria

1. The `WeatherStation` domain gains a `provider` attribute with values `none` (default) and `openweather`, set through a value object and exposed via station create/update.
2. The OWM association uses the station's existing latitude/longitude — no duplicate location is stored.
3. The `Measurement` domain gains a `source` attribute (`manual` default, `openweather`) that does not alter threshold/alert logic.
4. Persistence schemas and document mappers for stations and measurements are extended for the new fields, backward-compatible with existing documents (missing `provider`→`none`, missing `source`→`manual`).
5. Station DTOs/Swagger and measurement responses expose the new fields.
6. A seed/bootstrap creates a system owner account and three default `openweather` stations: Universidad Nacional de Quilmes, Buenos Aires, and Bariloche, idempotently (re-running does not duplicate).
7. Existing search/filter/alert behavior is unchanged for stations with `provider=none` and measurements with `source=manual`.
8. Unit tests cover the new value objects, entity behavior, mappers, and the seeding logic.

## Tasks / Subtasks

- [ ] Task 1: Add provider to the station domain (AC: #1, #2)
  - [ ] 1.1 Add a `WeatherProvider` value object / enum (`none`, `openweather`).

  - [ ] 1.3 Default to `none` when not provided.

- [ ] Task 2: Add source to the measurement domain (AC: #3)
  - [ ] 2.1 Add a `MeasurementSource` enum (`manual`, `openweather`).
  - [ ] 2.2 Thread `source` through `Measurement.create`, defaulting to `manual`.
  - [ ] 2.3 Confirm `AlertEvaluatorService`/threshold logic is untouched.

- [ ] Task 3: Persistence and mapping (AC: #4, #5)
  - [ ] 3.1 Extend `weather-station.schema.ts` and `measurement.schema.ts` with the new fields (defaults for back-compat).
  - [ ] 3.2 Update both document mappers and their specs.
  - [ ] 3.3 Expose fields in station DTOs and measurement response shape with Swagger props.

- [ ] Task 4: Default-station + system-owner seeding (AC: #6)
  - [ ] 4.1 Add an idempotent bootstrap (run on API start or via `npm run seed:*`).
  - [ ] 4.2 Create a system owner user the ingestion path can attribute stations to.
  - [ ] 4.3 Create the three default stations with coordinates and `provider=openweather`.

- [ ] Task 5: Tests (AC: #7, #8)
  - [ ] 5.1 Value object + entity unit tests for provider and source.
  - [ ] 5.2 Mapper specs for both directions including back-compat defaults.
  - [ ] 5.3 Seeding test: idempotent, creates exactly three stations + system owner.

## Dev Notes

- Default station coordinates (for the bootstrap):
  - Universidad Nacional de Quilmes — lat `-34.7206`, lon `-58.2659`.
  - Buenos Aires (Obelisco) — lat `-34.6037`, lon `-58.3816`.
  - Bariloche — lat `-41.1335`, lon `-71.3103`.
- `provider` and `source` are additive; do not change `StationAlertSettings` or the alert evaluation rules.
- Keep the value objects framework-free per the domain layer rules.
