# Story 3.11: Alerting — Prometheus Rules + Alertmanager Strategy

Status: draft

## Story

As an operator,
I want operational alerts on system and business health signals,
so that degradations (OWM failures, stalled ingestion, latency, outages) are surfaced proactively.

## Acceptance Criteria

1. Prometheus alert rules are defined for at least: high OWM error rate, circuit breaker stuck open, ingestion stalled (no measurements ingested in N minutes), high p95 endpoint latency, and a service being down.
2. An Alertmanager service is added to `docker-compose.yml` and receives alerts from Prometheus.
3. A documented routing strategy describes severities, grouping, throttling/inhibition, and at least one demonstrable receiver (e.g. a local webhook/log sink; optionally email/Telegram).
4. Each rule has sensible `for:` durations and labeled severity so flapping does not spam.
5. Alerts are reproducible in a demo (e.g. stopping OWM/the API triggers the corresponding alert) and the firing alert is visible in Alertmanager/Grafana.
6. The alerting strategy section is written for the architecture docs (S-03.14): what is monitored, thresholds, routing, and why.

## Tasks / Subtasks

- [ ] Task 1: Alert rules (AC: #1, #4)
  - [ ] 1.1 Author Prometheus rules using metrics from S-03.9 (OWM error rate, breaker state, ingestion gap, p95 latency, `up`).
  - [ ] 1.2 Set `for:` windows and severity labels.

- [ ] Task 2: Alertmanager (AC: #2, #3)
  - [ ] 2.1 Add `alertmanager` to `docker-compose.yml` and wire Prometheus `alerting`.
  - [ ] 2.2 Configure routing (grouping, throttling, inhibition) and a demonstrable receiver.

- [ ] Task 3: Validation + docs (AC: #5, #6)
  - [ ] 3.1 Demonstrate at least one alert firing by inducing a failure.
  - [ ] 3.2 Write the alerting-strategy section for the docs.

## Dev Notes

- Reuse the business/HTTP metrics from S-03.9; do not introduce new instrumentation here beyond what alert rules need.
- "Ingestion stalled" is a strong business alert — base it on `measurements_ingested_total{source="openweather"}` not increasing over a window.
- Keep rule and Alertmanager config under the versioned `infra/observability` folder.
