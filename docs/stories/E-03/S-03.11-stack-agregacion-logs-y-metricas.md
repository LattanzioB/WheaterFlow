# Historia 3.11: Stack de agregación de logs y métricas

Estado: borrador

## Historia

Como operador,
quiero logs centralizados y métricas Prometheus en los tres servicios,
para monitorear salud operativa antes de habilitar tracing distribuido end-to-end.

## Criterios de aceptación

1. api, ingest y notifications emiten logs JSON estructurados a stdout con `service` y campos de correlación.
2. Agregación de logs configurada (Loki + Promtail o ELK) accesible desde Docker Compose.
3. Cada servicio expone métricas Prometheus (`/metrics` o exportador OTel).
4. Métricas incluyen: duración/conteo HTTP, resultados OWM, tamaño batch ingest, publish/consume RabbitMQ, estado circuit breaker.
5. Counters custom: `owm_requests_total`, `measurements_ingested_total`, `alerts_published_total`.
6. Perfil Compose `observability` levanta Prometheus y Loki localmente.
7. README documenta URLs de logs y métricas.
