# Story 3.12: Monitoring Dashboard — Grafana (Hardware, Endpoint, Business)

Status: draft

## Story

As an operator,
I want a Grafana dashboard that shows hardware, per-endpoint, and business metrics,
so that I can monitor the health and activity of WeatherFlow at a glance.

## Acceptance Criteria

1. A Grafana service is added to `docker-compose.yml` with Prometheus (S-03.9), Loki (S-03.8), and Jaeger/Tempo data sources provisioned automatically.
2. A provisioned dashboard (versioned JSON, not hand-built only) contains three clearly labeled sections:
   - **Hardware:** CPU, memory/heap, event loop lag per service.
   - **Per-endpoint:** request rate, p95/p99 latency, and error rate by route.
   - **Business:** measurements ingested per minute (by source), alerts fired, OWM error rate, and circuit-breaker state.
3. The dashboard is available immediately after `docker compose up` (auto-provisioned, no manual import).
4. Panels render against real data produced by ingestion cycles and report/query traffic.
5. The dashboard links/correlates to logs (Loki) and traces (Jaeger) where practical (e.g. drilldown or documented navigation).
6. A short docs section explains each section and how it maps to the assignment's required metrics.

## Dev Notes

- Export the dashboard as versioned JSON under `infra/observability/grafana/dashboards` and provision it; avoid relying on manual UI edits.
- The business panels reuse the S-03.9 business metrics; verify the metric names match before building panels.
- Generating traffic with the k6 tests (S-03.13) is a convenient way to populate the per-endpoint panels for screenshots.
