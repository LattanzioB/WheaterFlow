# Historia 3.12: Tracing distribuido ingest → alerta en cola

Estado: borrador

## Historia

Como operador,
quiero tracing distribuido con OpenTelemetry entre ingest, API y notifications,
para seguir en una sola traza un ciclo completo desde el fetch OWM hasta la publicación de alerta en RabbitMQ.

## Criterios de aceptación

1. SDK OpenTelemetry en api, ingest y notifications con exportador OTLP a Jaeger/Tempo.
2. Auto-instrumentación HTTP, NestJS y MongoDB donde aplique.
3. Contexto propagado en cadena:
   - cron ingest → span HTTP OWM
   - ingest → span envío API
   - API record measurement → span publicación alerta
   - span consumer notifications
4. W3C `traceparent` propagado en llamadas ingest → API.
5. Contexto de trace inyectado en metadata de `ClimateAlertDetectedMessage` para continuidad en consumer.
6. Trace iniciado en ingest visible end-to-end en UI Jaeger/Tempo hasta publicación en cola.
7. Logs JSON incluyen `traceId`/`spanId` correlacionados con spans.
