# Story 3.13: Load Tests — k6 Scenarios Over Report/Query Endpoints

Status: draft

## Story

As an engineer,
I want at least three k6 load tests against the report/query endpoints with pass/fail thresholds,
so that the system's performance under load is measured and regressions are catchable.

## Acceptance Criteria

1. At least three k6 scenarios target the report/query endpoints (S-03.7 reports + the Delivery II `GET /measurements`): for example a steady **ramp** on current-temperature, a **spike** on last-day average, and a **soak**/sustained load on last-week average.
2. Each scenario defines thresholds (e.g. `http_req_duration p95 < target`, `http_req_failed < 1%`) so the run passes or fails objectively.
3. Scenarios are parameterized (base URL, VUs, duration, auth token) via env and documented.
4. Test scripts live in a versioned `load/` (or `test/load/`) folder with a README on how to run them and prerequisites (data seeded, services up).
5. Results can be exported to Prometheus/Grafana (or saved as summary JSON) so load traffic shows up on the dashboard (S-03.12).
6. A short results summary (throughput, latency percentiles, error rate, thresholds met) is captured for the docs (S-03.14).
7. The load tests run against a locally running stack and do not require external OWM calls (they hit read endpoints over already-ingested/seeded data).

## Tasks / Subtasks

- [ ] Task 1: Scenario scaffolding (AC: #3, #4)
  - [ ] 1.1 Create the `load/` folder with shared config (base URL, auth, VUs/duration via env).
  - [ ] 1.2 Add a README with prerequisites and run commands.

- [ ] Task 2: Three scenarios (AC: #1, #2)
  - [ ] 2.1 Ramp test on the current-temperature endpoint.
  - [ ] 2.2 Spike test on the last-day average endpoint.
  - [ ] 2.3 Soak/sustained test on the last-week average (and/or `GET /measurements`).
  - [ ] 2.4 Add thresholds to each scenario.

- [ ] Task 3: Results + integration (AC: #5, #6, #7)
  - [ ] 3.1 Configure k6 output to Prometheus/Grafana or summary JSON.
  - [ ] 3.2 Seed/prepare read data so runs do not depend on live OWM.
  - [ ] 3.3 Capture a results summary for the docs.

## Dev Notes

- Keep auth handling simple: obtain a JWT once (or use a pre-provisioned token) and reuse it across VUs.
- The report endpoints should be efficient (aggregation + indexes from S-03.7); use the load tests to confirm p95 stays within threshold and to justify the request cache if needed.
- Running k6 with the Prometheus remote-write output lets the dashboard show the generated traffic during a demo.
