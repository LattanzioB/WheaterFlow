# Historia 3.13: Pruebas de carga de consultas y reportes

Estado: completada

## Historia

Como desarrollador, quiero pruebas k6 reproducibles, para conocer el rendimiento
de consultas y reportes bajo distintos patrones de trafico.

## Criterios de aceptacion

1. Existe `npm run test:load` y configuracion versionada.
2. Hay al menos tres escenarios: rampa sostenida, pico y carga prolongada.
3. Se cubren busqueda de mediciones, temperatura actual y promedios.
4. Cada escenario define VUs, duracion, ramp-up y dataset.
5. Hay umbrales de p95, tasa de error y throughput.
6. Los escenarios de busqueda y promedios no dependen de OWM ni Telegram.
7. El escenario de temperatura actual usa ingesta con OWM **mockeado** (stub
   HTTP, WireMock o perfil de test) para evitar rate limits y flakiness de red.
8. Los resultados JSON/HTML y un baseline se guardan en `docs/load-tests`.

## Implementacion

- `npm run test:load` ejecuta `scripts/load-tests/weatherflow-load.js`.
- `npm run test:load:owm-stub` inicia un stub HTTP local compatible con el
  endpoint Current Weather de OpenWeatherMap.
- El `setup()` de k6 registra un usuario unico, crea una estacion
  `provider=openweather` y carga mediciones historicas sinteticas para que
  busqueda y promedios dependan solo de API + MongoDB.
- Los escenarios versionados son:
  - `sustained_ramp`: rampa sostenida sobre busqueda de mediciones y promedio
    diario.
  - `spike`: pico sobre busqueda, temperatura actual y promedio semanal.
  - `long_run`: carga prolongada sobre busqueda y promedios, con temperatura
    actual periodica.
- Los umbrales cubren p95 global y por endpoint, tasa de error y throughput.
- Los resultados se escriben en `docs/load-tests/latest-summary.json` y
  `docs/load-tests/latest-report.html`; el baseline inicial versionado queda en
  `docs/load-tests/baseline-summary.json` y
  `docs/load-tests/baseline-report.html`.
