# Historia 3.14: Panel de monitoreo y alertas operativas

Estado: completada

## Historia

Como operador, quiero un dashboard y reglas de alerta, para observar WeatherFlow
y reaccionar ante degradaciones durante operación y demostración.

## Criterios de aceptación

1. Grafana se provisiona con Prometheus y Loki.
2. El dashboard muestra CPU, memoria y reinicios por contenedor.
3. Muestra requests, errores y p95 por endpoint.
4. Muestra mediciones OWM por minuto, alertas, errores OWM, breakers y RabbitMQ.
5. El JSON del dashboard queda versionado y se carga automáticamente.
6. Prometheus incluye reglas para servicio caído, ingesta detenida, error OWM
   elevado y p95 alto.
7. Alertmanager tiene una ruta de demostración documentada y evita tormentas
   mediante agrupación, silencios y ventanas.
8. README explica cómo interpretar paneles y probar las alertas.

## Implementación

- Docker Compose agrega `alertmanager` y `cadvisor` al perfil
  `observability`; Prometheus monta reglas versionadas y envía alertas a
  Alertmanager.
- Grafana provisiona datasources con UIDs estables (`prometheus`, `loki`,
  `jaeger`) y carga automáticamente el dashboard versionado
  `WeatherFlow Operaciones`.
- El dashboard muestra CPU, memoria y reinicios aproximados por contenedor,
  requests/errores/p95 por endpoint, mediciones OWM por minuto, errores OWM,
  breakers, alertas publicadas y mensajes RabbitMQ consumidos.
- Las reglas Prometheus cubren servicio caído, ingesta scheduled detenida,
  error OWM elevado y p95 HTTP alto.
- Alertmanager usa una ruta webhook de demostración, agrupación, intervalos de
  reenvío e inhibición de warnings cuando existe una alerta crítica equivalente.
