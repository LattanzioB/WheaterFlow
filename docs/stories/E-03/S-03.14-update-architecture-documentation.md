# Story 3.14: Update Architecture Documentation And README For Delivery III

Status: draft

## Story

As a reviewer,
I want the architecture documentation and README updated for Delivery III,
so that the new ingestion service, resilience, observability, reports, and load tests are fully described and reproducible.

## Acceptance Criteria

1. C4 diagrams are updated: context (OpenWeatherMap as external system), container (new `ingestion` worker + observability stack: Prometheus, Grafana, Jaeger, Loki, Promtail, Alertmanager), and a component view of the ingestion service.
2. A sequence diagram shows the end-to-end ingestion flow: scheduler → OWM → intake → record → alert publish → notification dispatch, annotated with the distributed trace.
3. The ER/data-model docs reflect the new fields: station `provider` and measurement `source`, plus default stations.
4. A fault-tolerance section documents the strategies with the strategy→boundary→justification table (timeout, circuit breaker, bulkhead, fallback, request cache) and references the granularity-breaker reasoning for the standalone ingestion component.
5. An observability section documents log aggregation, metrics, distributed tracing, and the alerting strategy, with how to access Grafana/Jaeger/Prometheus.
6. A reports section documents the three endpoints (request/response, examples) and Swagger is current.
7. A load-testing section summarizes the k6 scenarios, thresholds, and results.
8. The root `README.md` documents the new env vars, how to run the full stack with `docker compose up`, and how to reach each tool (Swagger, Grafana, Jaeger, Prometheus, RabbitMQ UI).
9. `architecture-overview.md` is updated to describe the three-service topology and Delivery III scope.
