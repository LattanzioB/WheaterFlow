# Historia 3.15: Documentación de arquitectura de la Entrega III

Estado: pendiente

## Historia

Como revisor, quiero documentación sincronizada con la solución final, para
comprender la evolución arquitectónica y reproducir la demostración.

## Criterios de aceptación

1. C4 muestra API, notificaciones, ingesta, OWM y observabilidad.
2. Se justifican los desintegradores que motivan el componente independiente.
3. Hay secuencias para:
   - ingesta periódica (cron → OWM → API → persistencia),
   - alerta por medición OWM (API → RabbitMQ → notificaciones),
   - **temperatura actual** (cliente → API → ingesta → OWM → respuesta),
   - **promedios diario/semanal** (cliente → API → MongoDB → respuesta).
4. Swagger documenta proveedor, origen, endpoint interno y reportes.
5. Se documentan las estrategias de resiliencia y sus fronteras (OWM, API ↔
   ingesta).
6. Se documentan logs, métricas, tracing, reglas de alertas y dashboard.
7. Se adjuntan resultados de carga y evidencia de al menos una semana de datos.
8. README explica arranque, configuración, URLs y recorrido de demo.
9. Diagramas, enlaces y referencias pasan las validaciones del repositorio.
