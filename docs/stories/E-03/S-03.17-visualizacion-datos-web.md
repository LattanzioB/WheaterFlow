# Historia 3.17: Visualización de datos de la base en la web

Estado: pendiente

## Historia

Como usuario o revisor, quiero visualizar desde la web los datos persistidos
en MongoDB — gráficos de series de tiempo de las mediciones y tablas planas de
cada colección — para inspeccionar el estado del sistema sin depender de
Compass, mongosh o Swagger.

## Contexto

`apps/web` (React 19 + Vite, S-02.9) ya cubre los casos de uso con formularios
y tablas filtradas, pero no ofrece visualización gráfica ni una vista completa
de las colecciones. Las colecciones existentes son:

| Colección | Servicio dueño | Listado existente |
| --------- | -------------- | ----------------- |
| `users` | API | No hay listado (solo `GET /users/me`) |
| `weather_stations` | API | `GET /weather-stations` + `/available` (acotado al usuario) |
| `measurements` | API | `GET /measurements` con filtros |
| `user_notification_profiles` | Notificaciones | Solo el perfil propio vía `GET /users/me` |
| `notifications` | Notificaciones | `GET /notifications` (solo las propias) |

La web se extiende (no se crea una app nueva) y consume siempre datos vía REST
con JWT, siguiendo los patrones ya establecidos; nunca accede a MongoDB
directamente.

## Criterios de aceptación

1. La navegación de `apps/web` incorpora una sección "Datos" con dos áreas:
   gráficos de mediciones y tablas de colecciones.
2. **Series de tiempo:** un gráfico muestra la evolución de las mediciones de
   una estación con selector de estación, rango de fechas y métrica visible
   (temperatura, humedad, presión), alimentado por los filtros existentes de
   `GET /measurements`.
3. **Tablas planas:** existe una vista de solo lectura por cada una de las 5
   colecciones (`users`, `weather_stations`, `measurements`,
   `user_notification_profiles`, `notifications`) con sus columnas
   principales y paginación.
4. Los endpoints de listado que hoy no existen o están acotados al usuario se
   agregan como endpoints REST de solo lectura protegidos por JWT, en el
   servicio dueño de cada colección, sin modificar reglas de dominio.
5. Ningún dato sensible se expone: el hash de contraseña de `users` queda
   excluido de DTOs, respuestas y UI.
6. Los endpoints nuevos quedan documentados en Swagger (`@ApiTags`,
   `@ApiOperation`) y en `docs/api-reference.md`.
7. Los errores de la API se muestran con el `message` del servidor y la
   sección funciona con los datos reales de la ingesta OWM (estaciones UNQ,
   Buenos Aires y Bariloche).
8. La lógica de estado de las páginas nuevas tiene tests unitarios siguiendo
   el patrón existente (`notifications-page-state.spec.ts`).

## Tareas

- [ ] Definir y agregar los endpoints de listado faltantes (solo lectura,
      paginados, JWT): usuarios, perfiles de notificación y notificaciones a
      nivel colección; revisar el alcance de los listados de estaciones y
      mediciones para la vista completa.
- [ ] Excluir campos sensibles en los DTOs nuevos (hash de contraseña).
- [ ] Documentar los endpoints en Swagger y `docs/api-reference.md`.
- [ ] Elegir e integrar la librería de gráficos (propuesta: Recharts;
      alternativa: Chart.js — validar al iniciar la historia).
- [ ] Página de series de tiempo: selector de estación, rango de fechas,
      métricas conmutables.
- [ ] Páginas de tablas por colección con paginación y columnas principales.
- [ ] Entrada "Datos" en la navegación y rutas protegidas.
- [ ] Tests de estado de páginas y de los endpoints nuevos.
- [ ] Actualizar README de `apps/web` con el recorrido de la sección.

## Decisiones (validadas 2026-07-06)

| Tema | Decisión | Fecha |
| ---- | -------- | ----- |
| App | Extender `apps/web`, no crear una app nueva | 2026-07-06 |
| Contenido | Series de tiempo de mediciones + tablas planas de las 5 colecciones | 2026-07-06 |
| Acceso a datos | Siempre vía REST con JWT del servicio dueño; sin acceso directo a MongoDB desde la web | 2026-07-06 |

## Preguntas abiertas

1. **Visibilidad de las tablas completas:** ¿cualquier usuario autenticado
   puede ver todas las colecciones (propuesta por defecto, suficiente para un
   proyecto académico de demostración) o se restringe a un rol administrador?
   Si se exige rol, hay que agregar autorización por rol que hoy no existe.
2. **Librería de gráficos:** se propone Recharts por integración natural con
   React; confirmar antes de la tarea de integración.
