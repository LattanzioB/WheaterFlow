# Historia 3.2: Carga inicial de estaciones OpenWeather por defecto

Estado: completada

## Historia

Como operador, quiero estaciones OpenWeather disponibles desde el arranque, para
que la demostración y la ingesta no dependan de una carga manual.

## Criterios de aceptación

1. Se crean UNQ, Buenos Aires y Bariloche con coordenadas válidas.
2. Las tres estaciones quedan activas y con `provider=openweather`.
3. Existe un usuario de sistema estable que es dueño de las estaciones.
4. El bootstrap es idempotente y no genera duplicados.
5. Las pruebas verifican exactamente tres estaciones y su propietario.

## Implementación consolidada

- [x] `DefaultStationsBootstrap` integrado al arranque de la API.
- [x] Identificadores estables para usuario y estaciones.
- [x] Coordenadas de UNQ, Obelisco y Bariloche.
- [x] Prueba de idempotencia.
