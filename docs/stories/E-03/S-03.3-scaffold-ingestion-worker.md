# Story 3.3: Scaffold The `apps/ingestion` Worker (Scheduler, Config, Docker)

Status: draft

## Story

As the platform,
I want a new independently runnable ingestion service with a configurable scheduler,
so that periodic OpenWeatherMap polling runs in isolation from the user-facing API and notification services.

## Acceptance Criteria

1. A new `apps/ingestion` NestJS application is added to the Nest monorepo (build, start, and test scripts wired into `package.json` and `nest-cli.json`).
2. The service has its own configuration: OWM base URL/API key, target API base URL, `INGESTION_API_KEY`, and a configurable schedule (cron expression or interval) with Joi validation and `.env.example` entries.
3. A scheduler (e.g. `@nestjs/schedule`) triggers an ingestion cycle on the configured interval; the interval is overridable by env without code changes.
4. The service exposes a `/health` endpoint and (placeholder) `/metrics` endpoint consistent with the other services.
5. A `Dockerfile` builds the worker and a `ingestion` service is added to `docker-compose.yml`, depending on `api` and `rabbitmq`/`mongo` as needed, with a healthcheck.
6. The hexagonal/DDD folder layout (domain/application/infrastructure/interface) and project conventions match the existing services.
7. On startup with no provider-backed stations the cycle runs and no-ops cleanly (logs and exits the cycle without errors).
8. Unit tests cover config validation and the scheduler wiring (cycle invoked on tick).
