# Historia 3.4: Implementar adaptador HTTP OWM y mapeo de respuesta

Estado: borrador

## Historia

Como servicio ingest,
quiero un adaptador HTTP que consulte OpenWeatherMap y normalice la respuesta a una lectura interna,
para desacoplar el job de ingesta del formato y transporte específicos de OWM.

## Criterios de aceptación

1. Existe un puerto `WeatherDataProvider` en la capa de aplicación de ingest; OWM es la primera implementación.
2. El adaptador OWM llama a la Current Weather API usando latitud/longitud y API key desde configuración.
3. El cliente HTTP mapea la respuesta a DTO `ExternalWeatherReading` con temperatura, humedad, presión y timestamp.
4. El mapper maneja unidades explícitamente (Kelvin → Celsius si aplica).
5. Rate-limit y respuestas 4xx/5xx producen errores tipados con status HTTP y contexto de coordenadas.
6. Tests unitarios cubren mapper con fixtures JSON OWM y caminos de error (503, payload inválido).

## Tareas / subtareas

- [ ] Tarea 1: Definir puerto y DTOs (CA: #1, #3, #4)
  - [ ] 1.1 Crear puerto `WeatherDataProvider` y DTO `ExternalWeatherReading`.
  - [ ] 1.2 Implementar mapper OWM → DTO interno.

- [ ] Tarea 2: Implementar adaptador HTTP (CA: #2, #5)
  - [ ] 2.1 Agregar cliente HTTP (`@nestjs/axios`) con base URL e inyección de API key.
