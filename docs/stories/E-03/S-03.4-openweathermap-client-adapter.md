# Story 3.4: OpenWeatherMap Client Adapter And Reading Mapping

Status: draft

## Story

As the ingestion service,
I want a port and adapter that fetch current weather from OpenWeatherMap for a coordinate and map it to a domain reading,
so that external data can enter the system in the units and shape the domain expects.

## Acceptance Criteria

1. A `WeatherProviderClient` port defines `fetchCurrent(lat, lon): Promise<ProviderReading>` independent of OWM specifics.
2. An `OpenWeatherMapClient` adapter implements the port using the OWM Current Weather API and the configured API key.
3. The adapter maps OWM fields to the domain reading: temperature in °C (`units=metric`), humidity %, pressure hPa, and the observation timestamp.
4. Units and value ranges are normalized so readings are valid for the domain value objects (`Temperature`, `Humidity`, `Pressure`).
5. Non-2xx responses, malformed bodies, and missing fields raise typed errors the resilience layer (S-03.6) can act on (distinguishing client/4xx from transient/5xx/network).
6. The OWM API key is never logged; requests are constructed from configuration.
7. Unit tests use a mocked HTTP client (no real network) and cover success mapping, unit conversion, and each error category.

## Tasks / Subtasks

- [ ] Task 1: Define the port and reading model (AC: #1, #4)
  - [ ] 1.1 Add `WeatherProviderClient` port in the ingestion domain.
  - [ ] 1.2 Define a primitive `ProviderReading` (temp, humidity, pressure, observedAt, coords).

- [ ] Task 2: Implement the OWM adapter (AC: #2, #3, #6)
  - [ ] 2.1 Call OWM current weather with `units=metric` and the API key.
  - [ ] 2.2 Map `main.temp`, `main.humidity`, `main.pressure`, and `dt` to the reading.
  - [ ] 2.3 Build the URL from config; keep the key out of logs.

- [ ] Task 3: Error taxonomy (AC: #5)
  - [ ] 3.1 Throw a permanent error for 4xx (bad coords/key).
  - [ ] 3.2 Throw a transient error for 5xx/timeout/network.
  - [ ] 3.3 Throw a mapping error for malformed/missing fields.

- [ ] Task 4: Tests (AC: #7)
  - [ ] 4.1 Success: OWM payload maps to a valid reading.
  - [ ] 4.2 Conversion: metric units produce in-range domain values.
  - [ ] 4.3 Errors: 4xx, 5xx/network, and malformed body each map to the right error type.

## Dev Notes

- Use `axios` (already a dependency) behind the port; inject it so it can be mocked.
- Keep mapping logic pure and unit-testable; the adapter should only do HTTP + map.
- Do not add retries/timeouts here — those are resilience concerns wired in S-03.6 so the policy stays in one place.
