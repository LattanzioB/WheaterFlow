# Historia 3.6: Enviar mediciones OWM por el pipeline de dominio existente

Estado: borrador

## Historia

Como servicio ingest,
quiero enviar las lecturas OWM obtenidas al endpoint de mediciones de la API,
para que los datos externos persistan en la misma base y disparen el mismo flujo de alertas, cola y notificaciones que los reportes manuales.

## Criterios de aceptación

1. Ingest llama al endpoint existente de la API para registrar mediciones por cada fetch OWM exitoso.
2. Las mediciones incluyen referencia de estación, temperatura, humedad, presión y `reportedAt` desde observación OWM.
3. Las mediciones son distinguibles en persistencia (`source: openweather`) sin romper consultas/filtros existentes.
4. La evaluación de alertas corre por `RecordMeasurementService` sin reglas especiales para OWM.
5. Mediciones OWM con alerta publican `ClimateAlertDetectedMessage` en RabbitMQ y son consumidas por notifications.
6. Duplicados para misma estación y ventana de observación se manejan idempotentemente (política documentada).
7. Fallos de envío a la API se loguean con correlation id; ingest continúa con estaciones restantes.
8. Test de integración verifica: fetch OWM (mock) → persistencia API → alerta en cola → consumer recibe mensaje.
