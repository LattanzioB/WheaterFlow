# Story 3.6: Fault Tolerance On The OWM And Ingestion→API Boundaries

Status: draft

## Story

As the platform,
I want explicit fault-tolerance strategies on the external OpenWeatherMap boundary and the ingestion→API own-component boundary,
so that a slow or failing dependency degrades gracefully instead of cascading failures or losing data.

## Acceptance Criteria

1. At least three strategies are implemented; the target set is **five**, each justified by where it applies: timeout, circuit breaker, bulkhead, fallback, and request cache.
2. **Timeout:** OWM HTTP calls and ingestion→API calls have bounded, configurable timeouts.
3. **Circuit breaker:** the OWM client and the ingestion→API client each sit behind a breaker that opens after a configurable failure threshold and recovers via half-open probing; breaker state is observable (for metrics in S-03.9).
4. **Bulkhead:** the per-cycle OWM polling runs with bounded concurrency so a slow OWM cannot exhaust the worker or stall all stations.
5. **Fallback:** on OWM failure or open breaker, the cycle uses the last cached reading when available and otherwise skips that station without crashing the cycle.
6. **Request cache:** the last successful OWM response per location is cached (configurable TTL) and powers the fallback while avoiding redundant external calls.
7. Permanent errors (4xx) are not retried; transient errors are retried with bounded backoff before the breaker counts them.
8. All thresholds (timeouts, breaker limits, concurrency, TTL, retries) are configurable via env and documented; behavior is covered by unit tests with simulated failures (no real network).

## Tasks / Subtasks

- [ ] Task 1: Timeouts (AC: #2)
  - [ ] 1.1 Apply a configurable timeout to OWM requests.
  - [ ] 1.2 Apply a configurable timeout to ingestion→API requests.

- [ ] Task 2: Circuit breakers (AC: #3, #7)
  - [ ] 2.1 Wrap the OWM client in a breaker (closed/open/half-open) with configurable thresholds.
  - [ ] 2.2 Wrap the ingestion→API client in a breaker.
  - [ ] 2.3 Expose breaker state for metrics; retry transient errors with bounded backoff.

- [ ] Task 3: Bulkhead (AC: #4)
  - [ ] 3.1 Bound polling concurrency (worker pool / semaphore) per cycle.
  - [ ] 3.2 Make the concurrency limit configurable.

- [ ] Task 4: Request cache + fallback (AC: #5, #6)
  - [ ] 4.1 Cache the last successful OWM reading per location with a TTL.
  - [ ] 4.2 On failure/open breaker, serve the cached reading; otherwise skip the station.
  - [ ] 4.3 Tag/skip cleanly so a degraded cycle is still summarized (S-03.5).

- [ ] Task 5: Config + tests + docs (AC: #1, #8)
  - [ ] 5.1 Add all tunables to config/env and `.env.example`.
  - [ ] 5.2 Unit tests: timeout fires; breaker opens/half-opens/closes; bulkhead caps concurrency; cache hit serves fallback; 4xx not retried.
  - [ ] 5.3 Write the justification table (strategy → boundary → reason) for the docs (S-03.14).

## Dev Notes

- The assignment specifically expects protection at the OWM frontier (external, variable latency, possible outages) and between own components — cover both boundaries.
- A small, well-tested breaker/bulkhead (hand-rolled or a light library) is acceptable for an academic delivery; document the failure policy explicitly.
- The fallback choosing cached-vs-skip is the key resilience demo; make it observable so the dashboard (S-03.12) can show degraded cycles.
