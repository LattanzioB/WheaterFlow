# Historia 3.6: Registro remoto por el pipeline de dominio

Estado: completada

## Historia

Como servicio de ingesta, quiero enviar lecturas OWM a un endpoint interno de la
API, para reutilizar exactamente el pipeline de dominio de mediciones.

## Criterios de aceptación

1. La API expone `POST /internal/ingestion/measurements`.
2. El endpoint usa autenticación de sistema y no queda disponible como escritura
   pública anónima.
3. El request incluye estación, valores, `reportedAt`, `source=openweather` y una
   clave de idempotencia derivada de la observación OWM.
4. El controller invoca `RecordMeasurementService`; no escribe directo en Mongo.
5. Una lectura crítica publica `ClimateAlertDetectedMessage` y puede generar una
   notificación.
6. Reintentos no duplican una misma observación.
7. Se propaga un identificador de correlación.
8. Una prueba de integración cubre OWM simulado → API → Mongo → RabbitMQ.

## Implementación

- La API expone `POST /internal/ingestion/measurements`, protegido por
  `IngestionSystemTokenGuard` y el header `x-ingestion-token`.
- El contrato exige `stationId`, temperatura, humedad, presión, `reportedAt`,
  `source=openweather` y una clave de idempotencia SHA-256 de 64 caracteres.
- `InternalIngestionMeasurementsController` no accede a MongoDB: delega en
  `RecordMeasurementService`, que conserva validación, evaluación de alertas,
  persistencia y publicación de `ClimateAlertDetectedMessage`.
- `ApiMeasurementSubmitterAdapter` implementa el puerto
  `MeasurementSubmitter` en ingesta. Deriva la clave de
  `stationId + externalId OWM + observedAt` y llama al endpoint interno.
- `RecordMeasurementService` transforma la clave en un identificador estable y
  usa `saveIfAbsent()` para insertar de forma atómica. Un reintento devuelve la
  medición existente y no vuelve a publicar la alerta.
- El `cycleId` se propaga como `x-correlation-id`, se incorpora al mensaje de
  alerta y también se envía como propiedad AMQP `correlationId`.
- `RunIngestionCycleService` considera exitosa una estación cuando la lectura
  normalizada fue registrada por la API; los fallos de envío quedan aislados
  por estación igual que los fallos del proveedor.

## Pruebas

- Prueba de integración con lectura OWM simulada que atraviesa ingesta → API →
