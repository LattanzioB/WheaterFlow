# Historia 3.7: Resiliencia en frontera OpenWeatherMap

Estado: borrador

## Historia

Como ingeniero de plataforma,
quiero proteger las llamadas a OpenWeatherMap con time-out, circuit breaker y request cache,
para que latencia variable y caídas de la API externa no deriven en tormentas de reintentos ni bloqueen el batch de ingesta.

## Criterios de aceptación

1. El cliente HTTP OWM tiene time-out configurado (connect + response).
2. Las llamadas OWM están envueltas con circuit breaker (p. ej., `opossum` o interceptor Nest).
3. Existe request cache opcional para lat/lon idénticos dentro de TTL configurable.
4. Estado open/half-open del breaker y contadores cache hit/miss son expuestos como métricas.
5. Justificación documentada por estrategia: frontera protegida y modo de fallo esperado.
6. Tests unitarios: breaker abre tras umbral; time-out cancela request colgado; cache devuelve lectura reciente.
