# Historia 3.7: Resiliencia en la frontera OpenWeatherMap

Estado: completada

## Historia

Como operador, quiero proteger las llamadas a OWM desde ingesta, para que su
latencia o caída no agote recursos ni detenga la ingesta completa ni las
consultas síncronas de temperatura actual.

## Criterios de aceptación

1. El cliente OWM tiene timeout configurable.
2. Un circuit breaker abre y se recupera con umbrales documentados.
3. Un bulkhead limita consultas concurrentes por ciclo y por request síncrono.
4. Un request cache conserva la última lectura válida por ubicación y TTL.
5. Si OWM falla en ingesta programada, el sistema puede usar fallback controlado
   o saltear la estación, dejando explícita la antigüedad del dato.
6. Si OWM falla en consulta síncrona (S-03.9), ingesta devuelve error tipado
   que la API propaga como `502`/`503`/`504` (sin inventar datos).
7. Estado del breaker, cache hits/misses y fallos se exponen como métricas.
8. Las pruebas cubren timeout, apertura del breaker, bulkhead, cache y fallback.

## Implementación

- `OpenWeatherMapAdapter` conserva la responsabilidad HTTP pura de S-03.4:
  aplica `OWM_TIMEOUT_MS`, normaliza la respuesta y emite errores tipados.
- `ResilientWeatherDataProvider` envuelve ese adaptador y centraliza la frontera
  OWM con circuit breaker, bulkhead, request cache y métricas Prometheus.
- El breaker abre tras `OWM_BREAKER_FAILURE_THRESHOLD` fallos consecutivos
  (default `3`), rechaza solicitudes mientras dure `OWM_BREAKER_OPEN_MS`
  (default `30000`) y luego permite una prueba `half_open`; un éxito lo cierra
  y un fallo lo vuelve a abrir.
- El bulkhead usa `OWM_CONCURRENCY_LIMIT` también en el proveedor, por lo que
  protege tanto los ciclos batch como futuras consultas síncronas de S-03.9.
- La cache guarda la última lectura válida por coordenada durante
  `OWM_CACHE_TTL_MS` (default `300000`). Las lecturas cacheadas conservan
  `observedAt`; no se fabrican timestamps ni valores climáticos.
- En ingesta programada (`trigger=scheduled`), si OWM falla y existe una lectura
  cacheada vigente, el ciclo la envía al pipeline de dominio con metadata
  `fallback` (`reason`, `cachedAt`, `ageMs`, `ttlMs`). Si no hay cache vigente,
  la estación queda como `failed` y el lote continúa.
- En ejecuciones manuales y en la futura consulta síncrona de temperatura actual
  (S-03.9), los errores tipados se propagan sin usar fallback cacheado, para que
  la API pueda mapearlos a `502`/`503`/`504` sin inventar datos.
- `GET /metrics` en ingesta expone contadores de resultados OWM, fallos por
  código tipado, estado del breaker y entradas vigentes de cache.

## Pruebas

- `ResilientWeatherDataProvider`: cache hit con edad, apertura/cierre del
  breaker, rechazo por bulkhead y métricas.
- `RunIngestionCycleService`: fallback cacheado solo para `scheduled`; `manual`
  conserva el fallo tipado.
- `MetricsController`: renderizado Prometheus básico.
