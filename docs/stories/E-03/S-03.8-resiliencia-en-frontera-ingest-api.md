# Historia 3.8: Resiliencia en frontera ingest → API

Estado: borrador

## Historia

Como ingeniero de plataforma,
quiero proteger el envío de mediciones ingest → API con time-out y bulkhead,
para que una API lenta o caída parcial no bloquee el scheduler ni agote recursos del servicio ingest.

## Criterios de aceptación

1. El cliente HTTP de envío de mediciones tiene time-out configurado.
2. Envíos concurrentes limitados con bulkhead/semáforo (pool size configurable).
3. Reintentos solo en fallos idempotentes seguros (429/503 con backoff); política documentada.
4. Llamadas REST API → notifications restantes (Entrega II) incluyen time-out o circuit breaker donde falte.
5. Justificación documentada por estrategia y frontera protegida.
6. Tests unitarios: bulkhead rechaza concurrencia excesiva; time-out en envío colgado.
