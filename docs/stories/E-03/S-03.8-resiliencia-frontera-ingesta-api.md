# Historia 3.8: Resiliencia en fronteras API ↔ ingesta

Estado: completada

## Historia

Como operador, quiero proteger la comunicación REST entre API e ingesta, para
que una API lenta no bloquee el scheduler de ingesta ni que una ingesta caída
degrade los reportes de temperatura actual expuestos al cliente.

## Criterios de aceptación

### Frontera ingesta → API (envío de mediciones, S-03.6)

1. El cliente interno tiene timeout y circuit breaker configurables.
2. Un bulkhead limita envíos simultáneos.
3. Solo se reintentan 429, 502, 503, 504 y errores de red seguros.
4. Los reintentos usan backoff con jitter y la clave de idempotencia de S-03.6.
5. Los errores definitivos se registran por estación sin cancelar el lote.

### Frontera API → ingesta (reporte temperatura actual, S-03.9)

6. El cliente HTTP de la API hacia ingesta tiene timeout configurable.
7. Un circuit breaker o bulkhead evita saturar ingesta ante picos de consultas.
8. Fallos de ingesta se mapean a respuestas HTTP claras sin exponer stack traces.
9. Los reintentos en el read path son conservadores (máximo 1) o están
   deshabilitados si aumentan latencia p95; la política queda documentada.

### Observabilidad y pruebas

10. Se exponen métricas de intentos, reintentos, rechazos y estado del breaker
    en ambas direcciones.
11. Las pruebas cubren saturación, timeout, retry seguro y fallo definitivo en
    cada frontera.

## Implementación

### Ingesta → API

- `ApiMeasurementSubmitterAdapter` protege
  `POST /internal/ingestion/measurements` con timeout Axios configurable,
  bulkhead, circuit breaker y reintentos con backoff exponencial y jitter.
- `API_TIMEOUT_MS`, `API_CONCURRENCY_LIMIT`,
  `API_BREAKER_FAILURE_THRESHOLD`, `API_BREAKER_OPEN_MS`,
  `API_RETRY_ATTEMPTS` y `API_RETRY_BASE_DELAY_MS` gobiernan la frontera.
- Solo se reintentan `429`, `502`, `503`, `504`, timeouts y errores de red
  seguros. Los errores definitivos se propagan al ciclo como fallo de estación,
  por lo que no cancelan el lote completo.
- La clave de idempotencia se calcula una vez por lectura OWM y se reutiliza en
  todos los intentos de envío, manteniendo la semántica de S-03.6.

### API → ingesta

- `ApiToIngestionCurrentWeatherClient` prepara la frontera de lectura para
  S-03.9 con timeout Axios configurable, bulkhead, circuit breaker, métricas y
  política conservadora de retry.
- `INGESTION_SERVICE_URL`, `INGESTION_TIMEOUT_MS`,
  `INGESTION_CONCURRENCY_LIMIT`, `INGESTION_BREAKER_FAILURE_THRESHOLD`,
  `INGESTION_BREAKER_OPEN_MS`, `INGESTION_RETRY_ATTEMPTS` y
  `INGESTION_RETRY_BASE_DELAY_MS` configuran el cliente.
- La política por defecto permite como máximo un retry en el read path para
  evitar degradar latencia p95. Fallos agotados se mapean a `502`, `503` o
  `504` mediante errores tipados, sin exponer stack traces.
- El cliente apunta al contrato interno de S-03.9:
  `GET /internal/weather/current?latitude=&longitude=` con
  `x-ingestion-token`, pero la ruta pública y el endpoint interno se mantienen
  para la historia S-03.9.

### Observabilidad

- La serie `weatherflow_http_boundary_requests_total` expone intentos,
  reintentos, fallos, rechazos por bulkhead y rechazos por circuito abierto.
- La serie `weatherflow_http_boundary_breaker_state` expone el estado del
  breaker por dirección (`ingestion_to_api` y `api_to_ingestion`).
- Ingesta conserva las métricas OWM existentes y agrega las métricas REST
  internas en `GET /metrics`; la API expone las métricas REST internas en
  `GET /metrics`.

## Justificación por frontera

| Frontera | Timeout | Bulkhead | Breaker | Retry |
| -------- | ------- | -------- | ------- | ----- |
| Ingesta → API | `API_TIMEOUT_MS` evita bloquear workers ante API lenta. | `API_CONCURRENCY_LIMIT` limita envíos simultáneos. | `API_BREAKER_FAILURE_THRESHOLD` y `API_BREAKER_OPEN_MS` evitan insistir sobre API degradada. | Hasta `API_RETRY_ATTEMPTS`, solo transitorios seguros, con idempotencia estable. |
| API → ingesta | `INGESTION_TIMEOUT_MS` acota latencia del reporte actual. | `INGESTION_CONCURRENCY_LIMIT` evita saturar ingesta ante picos. | `INGESTION_BREAKER_FAILURE_THRESHOLD` y `INGESTION_BREAKER_OPEN_MS` protegen ingesta y devuelven `503` claro. | `INGESTION_RETRY_ATTEMPTS` default `1`; conservador para no empeorar p95. |

## Pruebas

- `ApiMeasurementSubmitterAdapter`: idempotencia/correlación, retry seguro,
  fallo definitivo sin retry, bulkhead y apertura de circuit breaker.
- `ApiToIngestionCurrentWeatherClient`: lectura normalizada, retry conservador,
  fallo definitivo sin retry, bulkhead, timeout, apertura de breaker y mapeo a
  HTTP claro.
- `MetricsController` y validación de entorno cubren exposición de métricas y
  configuración de ambas fronteras.
