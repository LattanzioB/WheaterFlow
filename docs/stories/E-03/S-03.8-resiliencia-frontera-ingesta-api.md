# Historia 3.8: Resiliencia en la frontera ingesta → API

Estado: pendiente

## Historia

Como operador, quiero proteger el envío remoto a la API, para que una API lenta
o temporalmente caída no bloquee el scheduler.

## Criterios de aceptación

1. El cliente interno tiene timeout y circuit breaker configurables.
2. Un bulkhead limita envíos simultáneos.
3. Solo se reintentan 429, 502, 503, 504 y errores de red seguros.
4. Los reintentos usan backoff con jitter y la clave de idempotencia de S-03.6.
5. Los errores definitivos se registran por estación sin cancelar el lote.
6. Se exponen métricas de intentos, reintentos, rechazos y estado del breaker.
7. Las pruebas cubren saturación, timeout, retry seguro y fallo definitivo.
