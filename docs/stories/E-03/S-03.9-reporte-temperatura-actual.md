# Historia 3.9: Reporte de temperatura actual (OWM en tiempo real)

Estado: completada

## Historia

Como cliente de la API, quiero consultar la temperatura actual de una estacion
con proveedor OpenWeather, para obtener el clima en tiempo real desde OWM usando
las coordenadas de la estacion, sin leer la ultima medicion persistida.

## Criterios de aceptacion

### API (fachada publica)

1. `GET /stations/:stationId/reports/temperature/current` expone el reporte al
   cliente autenticado.
2. Solo aplica a estaciones con `provider=openweather`; las demas devuelven un
   error documentado (p. ej. `422 Unprocessable Entity`).
3. Estacion inexistente devuelve `404`.
4. La API resuelve la estacion, valida el proveedor y delega en ingesta via REST
   (`API -> ingestion -> OWM`). No consulta MongoDB ni llama a OWM directamente.
5. La respuesta incluye: id/nombre de estacion, temperatura, unidad (`celsius`),
   `observedAt` (timestamp OWM) y `fetchedAt` (momento de la consulta).
6. Errores de ingesta u OWM se mapean a respuestas HTTP claras (`502`, `503`,
   `504`) sin filtrar detalles internos del proveedor.
7. La consulta **no** persiste automaticamente la lectura (la persistencia
   periodica sigue en S-03.5/S-03.6).

### Ingesta (endpoint interno)

8. Ingesta expone un endpoint REST interno
   `GET /internal/weather/current?latitude=&longitude=` que reutiliza el puerto
   `WeatherDataProvider` de S-03.4.
9. El endpoint interno consulta OWM en tiempo real y devuelve la lectura
   normalizada.
10. El endpoint requiere autenticacion de sistema con `x-ingestion-token`.
11. Swagger de la API documenta el reporte publico; ingesta documenta el
    contrato interno en `docs/api-reference.md` y en `libs/contracts`.

### Pruebas

12. Tests unitarios en API con cliente de ingesta mockeado.
13. Tests unitarios en ingesta con `WeatherDataProvider` mockeado.
14. Test de integracion opcional: API -> ingesta -> OWM mockeado.

## Implementacion

- `GET /stations/:stationId/reports/temperature/current` queda expuesto en la
  API como fachada autenticada. El controller delega en
  `GetCurrentTemperatureReportService`, que resuelve la estacion, valida
  `provider=openweather` y llama a ingesta mediante
  `ApiToIngestionCurrentWeatherClient`.
- `GET /internal/weather/current?latitude=&longitude=` queda expuesto en
  ingesta con `x-ingestion-token`; reutiliza el puerto `WeatherDataProvider`
  protegido por S-03.7 y devuelve la lectura normalizada de OWM.
- `libs/contracts/src/weather/current-weather.ts` centraliza el contrato de
  lectura interna y la respuesta publica de reporte actual.
- La respuesta publica incluye id/nombre de estacion, temperatura en Celsius,
  `observedAt` proveniente de OWM y `fetchedAt` de la consulta API.
- La consulta no persiste mediciones ni lee la ultima medicion de MongoDB; la
  persistencia periodica sigue en S-03.5/S-03.6.

## Errores

- Estacion inexistente: `404`.
- Estacion sin `provider=openweather`: `422`.
- Timeout en ingesta u OWM: `504`.
- Ingesta/OWM saturado, no disponible o con circuito abierto: `503`.
- Respuesta invalida o fallo no clasificado en el proveedor: `502`.

## Pruebas

- `GetCurrentTemperatureReportService`: delegacion por coordenadas y rechazo de
  proveedores no OpenWeather.
- `StationTemperatureReportsController`: respuesta exitosa y mapeo `404`,
  `422`, `502`, `503`, `504`.
- `CurrentWeatherController`: consulta OWM normalizada y mapeo de errores de
  proveedor.

## Notas de desarrollo

- OWM solo se consume desde ingesta; la API actua como fachada REST hacia el
  cliente.
- S-03.7 protege la frontera ingesta -> OWM (cron y consultas sincronas).
- S-03.10 (promedios) sigue usando solo MongoDB; no confundir semanticas.
- Depende de S-03.1 (proveedor), S-03.3 (shell ingesta), S-03.4 (adaptador OWM)
  y S-03.8 (resiliencia API -> ingesta).
