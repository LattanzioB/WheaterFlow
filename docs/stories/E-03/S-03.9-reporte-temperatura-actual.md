# Historia 3.9: Reporte de temperatura actual (OWM en tiempo real)

Estado: pendiente

## Historia

Como cliente de la API, quiero consultar la temperatura actual de una estación
con proveedor OpenWeather, para obtener el clima en tiempo real desde OWM usando
las coordenadas de la estación, sin leer la última medición persistida.

## Criterios de aceptación

### API (fachada pública)

1. `GET /stations/:stationId/reports/temperature/current` expone el reporte al
   cliente autenticado.
2. Solo aplica a estaciones con `provider=openweather`; las demás devuelven un
   error documentado (p. ej. `422 Unprocessable Entity`).
3. Estación inexistente devuelve `404`.
4. La API resuelve la estación, valida el proveedor y delega en ingesta vía REST
   (`API → ingestion → OWM`). No consulta MongoDB ni llama a OWM directamente.
5. La respuesta incluye: id/nombre de estación, temperatura, unidad (`celsius`),
   `observedAt` (timestamp OWM) y `fetchedAt` (momento de la consulta).
6. Errores de ingesta u OWM se mapean a respuestas HTTP claras (`502`, `503`,
   `504`) sin filtrar detalles internos del proveedor.
7. La consulta **no** persiste automáticamente la lectura (la persistencia
   periódica sigue en S-03.5/S-03.6).

### Ingesta (endpoint interno)

8. Ingesta expone un endpoint REST interno (p. ej.
   `GET /internal/weather/current?latitude=&longitude=` o por `stationId`) que
   reutiliza el puerto `WeatherDataProvider` de S-03.4.
9. El endpoint interno consulta OWM en tiempo real y devuelve la lectura
   normalizada.
10. El endpoint requiere autenticación de sistema (token o red interna
    documentada).
11. Swagger de la API documenta el reporte público; ingesta documenta el
    contrato interno en `docs/api-reference.md` o contrato compartido en
    `libs/contracts`.

### Pruebas

12. Tests unitarios en API con cliente de ingesta mockeado.
13. Tests unitarios en ingesta con `WeatherDataProvider` mockeado.
14. Test de integración opcional: API → ingesta → OWM mockeado.
